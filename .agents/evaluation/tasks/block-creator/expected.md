# Expected: block-creator

## Input

- Prompt: `prompt.md` в этой папке.
- Контекст: текущий проект и скилл `.agents/skills/page-constructor-block-creator/`.
- Запуск: свежая сессия и одноразовая рабочая копия с зависимостями; `expected.md` читается после выполнения.
- Проектные документы: `.agents/docs/architecture.md`, `memory-bank/README.md`, релевантные usage/dependency docs, `.agents/docs/navigation.md` и `.agents/docs/storybook.md`.

## Expected output

- Создан работающий Promo: заголовок, подзаголовок, фоновое изображение, одна CTA-кнопка и поддержка светлой/тёмной темы.
- Реализация и стили находятся в `src/blocks/Promo/`; публичные props/model доступны через модельный API, новая модель включена в `BlockModels`. BEM использует короткое имя без пространства имён.
- `form.ts` содержит дескрипторы `Fields` и начальные данные; `icon.ts` предоставляет превью.
- `index.ts` экспортирует одну конфигурацию `@gravity-ui/page-constructor/promo-block`, зарегистрированную в `src/blocks/index.ts`. Форма, начальные данные и иконка подключены к конфигурации.
- Для нового блока не созданы `schema.ts` и регистрации AJV; `schema` внутри `index.ts` остаётся метаданными редактора. При необходимости добавлены преобразования текста.
- Светлая и тёмная истории действительно выбирают нужные ресурсы: проверен используемый компонентом контекст темы; одного prop `theme` недостаточно для такого вывода.
- Storybook содержит `Blocks/Promo` с `Default` и `DarkTheme`, осмысленными данными, MDX, прямым импортом реализации и `parameters.inputs: form`.
- Обновлены записи `memory-bank/`; граф использования содержит фактических потребителей или явно отмечает их отсутствие.
- Итоговый ответ перечисляет прочитанные документы, изменения и фактические результаты применимых проверок из `.agents/validation/README.md`, включая Storybook и форму. Блокеры и непроверенное поведение указаны явно.

## Disqualifiers (any one = FAIL)

- Представлен только план вместо реализации.
- Созданы `index_deprecated.ts`, старый тип, legacy enum/map/template или старый псевдоним схемы для нового блока.
- Для нового блока созданы legacy AJV-схема или регистрации AJV либо удалено поле `schema` с метаданными редактора из конфигурации.
- Заявлено успешное выполнение проверок без фактического запуска.

## Scoring rubric (5 points; pass = 5/5)

1. Соблюдён Pre-response gate, перечислены прочитанные проектные документы.
2. Реализованы запрошенные поля, стили с коротким BEM-именем, публичные модели с включением в `BlockModels` и только новая конфигурация.
3. Форма, начальные данные и иконка подключены и проверены в интерфейсе.
4. Выполнены регистрации каталога и необходимых преобразований без добавления AJV; обновлён memory-bank.
5. Обе истории действительно отображаются; приведены результаты применимых проектных проверок.

Любой disqualifier означает FAIL независимо от суммы. Отсутствующие доказательства отмечаются как unverified, а не pass. План или наличие исходника истории не доказывает работу интерфейса.
